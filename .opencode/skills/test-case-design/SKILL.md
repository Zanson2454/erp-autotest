# Test Case Design Skill

## 适用场景
当用户提出以下任务时，优先使用本技能：
- 设计测试用例
- 补充测试点
- 做需求测试分析
- 输出功能测试范围
- 设计 ERP / 供应链业务测试场景

## 输入信息要求
尽量基于以下信息设计：
- 需求说明 / PRD / 原型 / 流程图
- 接口文档
- 字段规则
- 状态流转规则
- 角色权限
- 上下游依赖
- 非功能要求（性能、安全、兼容性）

## 执行步骤
1. 理解业务目标
   - 这个功能解决什么问题
   - 谁会使用
   - 关键业务规则是什么

2. 拆解测试维度
   - 功能主流程
   - 异常流程
   - 边界值
   - 数据约束
   - 权限控制
   - 状态流转
   - 并发/重复提交
   - 上下游联动
   - 回归影响面

3. 提炼测试点
   - 输入类测试点
   - 规则类测试点
   - 流程类测试点
   - 数据类测试点
   - 展示类测试点
   - 接口类测试点

4. 形成可执行用例
   - 前置条件
   - 操作步骤
   - 输入数据
   - 预期结果
   - 优先级

5. 标记高风险项
   - 金额
   - 库存
   - 状态机
   - 权限
   - 定时任务
   - 第三方对接

## 输出格式
优先输出 Markdown 表格：

| 用例ID | 模块 | 测试点 | 前置条件 | 测试步骤 | 测试数据 | 预期结果 | 优先级 |
|---|---|---|---|---|---|---|---|

然后补充以下内容：

### 测试范围
- 包含：
- 不包含：

### 风险点
- 

### 回归建议
- 

## 注意事项
- 用例不要只写正常流，必须覆盖异常流和边界值
- 预期结果必须可判断，不要写模糊描述
- ERP / 供应链场景重点关注：
  - 单据状态流转
  - 数据权限
  - 仓库/库存变更
  - 金额与税费
  - 单据关联关系
  - 作废/反审/逆向操作
