# Code Review Skill

## 适用场景
当用户提出以下任务时，优先使用本技能：
- 审查 PR / diff
- 检查代码风险
- 评估发布风险
- 提出 review 意见
- 从测试/质量角度审查改动

## 输入信息要求
- 改动说明
- diff / patch / 提交记录
- 相关模块背景
- 测试范围
- 业务规则
- 关联接口 / 表 / 配置

## 执行步骤
1. 先理解改动目标
2. 再检查实现是否满足目标
3. 按以下维度审查
   - 正确性
   - 边界条件
   - 异常处理
   - 幂等与并发
   - 可读性与可维护性
   - 测试覆盖
   - 回滚与发布风险
4. 输出 review 结论
   - 必改问题
   - 建议优化
   - 可接受风险

## 注意事项
- review 不要只看代码风格，要优先看业务正确性
- 测试视角要重点关注未覆盖的边界和异常场景
- 对 ERP 场景要重点看状态、库存、金额、权限、组织隔离
