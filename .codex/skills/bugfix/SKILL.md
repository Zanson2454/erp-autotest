# Bugfix Skill

## 适用场景
当用户提出以下任务时，优先使用本技能：
- 修复某个明确缺陷
- 分析报错日志并给出修复方案
- 排查接口异常、数据异常、业务状态异常
- 修复线上/测试环境发现的问题
- 对某个问题做最小范围修复并评估影响面

## 输入信息要求
执行前尽量收集以下信息：
- 问题现象
- 复现步骤
- 期望结果
- 实际结果
- 报错日志 / 堆栈
- 请求参数 / 响应数据
- 涉及的模块、接口、表、任务
- 最近变更记录
- 是否线上问题、影响范围、优先级

如果输入信息不足，先基于已有上下文做合理假设，并在输出中明确假设条件。

## 执行步骤
1. 明确问题定义
   - 用一句话总结问题本质
   - 标记影响对象：用户、订单、库存、供应商、采购单、结算单等
   - 判断问题类型：前端展示、接口逻辑、数据库数据、异步任务、配置问题

2. 梳理复现链路
   - 找到入口
   - 确认前置数据
   - 明确触发动作
   - 明确异常结果
   - 如无法完整复现，构造最小复现路径

3. 定位根因
   - 先看日志、异常栈、SQL、调用链
   - 核对入参、出参、状态机流转
   - 核对边界条件：空值、重复提交、并发、脏数据、权限、时间条件
   - 对比正常路径和异常路径差异
   - 明确根因，不要只停留在现象层

4. 设计修复方案
   - 优先最小改动
   - 避免引入额外副作用
   - 必要时增加保护性判断、幂等控制、异常提示、日志埋点
   - 若涉及数据修复，代码修复和数据修复要分开描述

5. 实施修复
   - 修改代码
   - 保持代码风格一致
   - 必要时补充注释，但不要堆砌无效注释

6. 验证修复
   - 验证原问题已修复
   - 验证主流程未受影响
   - 验证相关边界场景
   - 补充单测 / 集成测试 / 接口测试

7. 评估影响面
   - 同类接口
   - 同类状态流转
   - 同类数据模型
   - 相关定时任务 / 下游联动 / 上游调用方

请严格按以下结构输出：

### 1. 问题总结
- 问题现象：
- 影响范围：
- 严重程度：
- 是否可稳定复现：

### 2. 根因分析
- 直接原因：
- 深层原因：
- 涉及模块：
- 涉及数据表 / 接口：

### 3. 修复方案
- 修复思路：
- 修改点：
- 是否涉及数据库修复：

### 4. 验证方案
- 复现用例：
- 修复验证点：
- 回归验证点：
- 边界验证点：

### 5. 交付内容
- 代码修改摘要：

## 注意事项
- 不要在根因未明确前直接大改代码
- 优先最小修复，不随意做顺手重构
- 需要区分“代码缺陷”和“脏数据导致的问题”
- 涉及 ERP / 供应链场景时，重点关注状态流转、库存一致性、金额计算、权限隔离、幂等控制
- 如果证据不足，要明确写出“当前为推测，需要补充日志/数据验证”
