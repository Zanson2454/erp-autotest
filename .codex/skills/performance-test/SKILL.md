# Performance Test Skill

## 适用场景
当用户提出以下任务时，优先使用本技能：
- 设计压测方案
- 编写 JMeter / Locust 压测建议
- 分析接口性能瓶颈
- 输出性能测试报告框架
- 做容量评估和风险评估

## 输入信息要求
尽量具备以下信息：
- 测试目标
- 被测接口 / 服务 / 任务
- 业务场景
- 目标 TPS / QPS
- 并发用户数
- 响应时间目标
- 错误率目标
- 测试环境规格
- 数据量级
- 上下游依赖
- 缓存/消息队列/数据库信息

## 执行步骤
1. 明确性能目标
   - 吞吐量
   - 响应时间
   - 错误率
   - 稳定性
   - 容量上限

2. 识别关键场景
   - 核心交易链路
   - 高频查询接口
   - 批量处理
   - 异步任务
   - 大数据量分页/导出/导入

3. 设计压测模型
   - 基准测试
   - 负载测试
   - 稳定性测试
   - 峰值测试
   - 容量测试

4. 明确观测指标
   - RT：平均、P90、P95、P99
   - TPS / QPS
   - 错误率
   - CPU
   - 内存
   - GC
   - 线程池
   - 连接池
   - SQL 慢查询
   - Redis / MQ 指标

5. 分析瓶颈
   - 应用瓶颈
   - 数据库瓶颈
   - 缓存瓶颈
   - 网络瓶颈
   - 下游依赖瓶颈
   - 锁竞争 / 线程池耗尽 / 连接池不足

6. 输出优化建议
   - 代码级
   - SQL 级
   - 架构级
   - 配置级
   - 数据级

- 应用指标：
- 系统指标：

- 响应时间表现：

- 短期建议：
- 中期建议：

## 注意事项
- 压测前必须确认环境隔离和数据可控
- 必须说明是否包含下游真实依赖
- 不能只看平均响应时间，要看 P95/P99
- ERP 场景重点关注：
  - 大列表查询
  - 批量导入导出
  - 单据提交/审核
  - 库存扣减
  - 定时结算/对账任务
