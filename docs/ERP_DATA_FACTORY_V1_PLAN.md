# ERP Data Factory V1 落地计划

## 1. 北极星目标（时刻不忘）

将 ERP 数据工厂建设为**面向业务场景的数据基础设施产品**，而不是零散造数脚本集合，满足以下长期目标：

1. 同一能力内核，同时服务开发阶段与自动化测试阶段的数据创建。
2. 对外统一提供 `CLI + FastAPI`，对内提供 Python SDK（pytest 可直接调用）。
3. 模块按独立产品设计，具备清晰边界、可扩展能力注册、可观测执行链路。
4. 代码仓先与当前自动化仓同仓维护，但架构上保持独立产品化。

## 2. V1 总体策略

1. 新建独立产品包：`erp_data_factory`。
2. V1 只覆盖“当前已被引用的能力”，避免一次性大爆炸改造。
3. 统一执行模式：`API-first`（业务写入走接口；DB 用于查询、校验和兜底读取）。
4. 新入口作为主路径，兼容层统一收敛在 `erp_data_factory.compat`（迁移期间可控）。

## 3. 短期优先目标（第一优先级）

短期你要的效果是：**先完成主数据造数能力中的组织、物料、伙伴**。  
V1 第一阶段先交付以下场景能力：

1. 组织主数据构造（Org）
2. 物料主数据构造（Material）
3. 伙伴主数据构造（Partner，含客户/供应商）

对应三端落地目标：

1. SDK：`client.master.org/material/partner` 可直接调用。
2. CLI：可通过场景命令执行上述三类造数。
3. FastAPI：可通过统一场景执行接口触发上述三类造数。

## 4. 分阶段实施计划

### Phase 1：主数据能力先行（Org/Material/Partner）

1. 搭建 `erp_data_factory` 最小可运行骨架（core/domain/interfaces）。
2. 定义并注册 3 个主数据场景（org/material/partner）的输入输出契约。
3. 打通 SDK + CLI + FastAPI 三端调用同一 application 层。
4. 为 pytest 提供 fixture 与直接 SDK 两种接入方式。
5. 验证主数据场景在 `test` 环境可稳定执行并返回标准结果。

### Phase 2：已引用能力迁移（当前计划内）

1. 迁移 bootstrap 能力（env/base/cache）。
2. 迁移采购与交付核心场景（PO/DN）。
3. 迁移财务 AP/AR 当前用例已引用的方法能力。
4. 将调用方逐步切到新 SDK 主路径，旧入口仅保留兼容层。

### Phase 3：产品化增强

1. 增加能力清单、统一错误码、执行审计上下文（request_id/scenario_key/profile）。
2. 增加可选异步任务模式（进程内任务管理）。
3. 评估后续清理能力、队列化任务、跨仓拆分的时机。

## 5. 关键接口形态（V1 约束）

1. FastAPI 前缀：`/erp-data-factory/v1`
2. 统一执行接口：`POST /scenarios/{scenario_key}:run`
3. CLI 形态：`edf scenario run <scenario_key> ...`
4. SDK 形态：领域 Facade + 通用 `run(scenario_key, payload)` 并存

## 6. 验收标准（尤其针对短期目标）

### A. 主数据短期验收（必须先达成）

1. Org/Material/Partner 三类场景在 SDK/CLI/API 三端都能执行成功。
2. 返回结构统一，至少包含：`success`、`scenario_key`、`data`、`trace_id`。
3. 可在 pytest 中直接消费输出结果用于后续用例前置准备。

### B. 稳定性与可维护性验收

1. 失败错误有统一分类（参数错误/配置错误/上游接口错误/数据缺失）。
2. 执行日志可定位到具体场景与 profile。
3. 兼容层不阻断现有链路，迁移可渐进推进。

## 7. 风险与控制

1. 风险：一次迁移过多能力导致交付拉长。  
   控制：先锁定主数据三场景，按阶段交付。
2. 风险：新旧路径并存导致维护负担上升。  
   控制：兼容层只做薄转发，不新增业务逻辑。
3. 风险：接口契约不稳定影响 pytest 适配。  
   控制：先固化主数据场景契约并加契约测试。

## 8. 里程碑定义

1. M1（短期目标达成）：Org/Material/Partner 三场景三端可用。
2. M2（迁移达成）：当前已引用能力迁移到新产品包主路径。
3. M3（产品化增强）：异步执行、能力清单、标准错误治理完成。
